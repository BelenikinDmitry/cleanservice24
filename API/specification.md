# Описание приложения для заявки на доступ к API Яндекс Директа

Черновик по шаблону из `task.txt`. Заполнен по фактическому состоянию приложения (`API/prototype/`).
Перед отправкой проверьте пункты, отмеченные **[заполнить]**.

## 1. Общее описание и назначение системы

«CleanService24 Ads Manager» — внутренний инструмент одного рекламодателя, клининговой компании CleanService24 (cleanservice24.ru). Приложение не агентское и не публичное: работает только с рекламными кампаниями самой компании, доступ имеют сотрудники компании.

Назначение:
- загрузка текстовых объявлений, подготовленных по направлениям клининга, с проверкой на соответствие лимитам Директа до отправки;
- просмотр списка кампаний и их статусов;
- регулярная выгрузка статистики (показы, клики, CTR, расход, CPC) по дням и по кампаниям.

Приложение не дублирует интерфейс Директа: цель — убрать ручной перенос десятков объявлений и ручную выгрузку отчётов.

## 2. Сценарий использования

1. Сотрудник открывает приложение и нажимает «Подключить аккаунт Директа»; авторизация идёт по OAuth 2.0 (Яндекс ID). Токен хранится только в памяти сервера на время сессии.
2. На странице «Кампании» приложение запрашивает список кампаний аккаунта.
3. На странице «Объявления» приложение читает подготовленный файл с объявлениями, проверяет длину заголовков, текстов, ссылок и уточнений. Для объявлений без нарушений сотрудник указывает ID группы объявлений и подтверждает отправку.
4. На странице «Отчёты» сотрудник выбирает период и разбивку (по дням / по кампаниям) и получает таблицу и графики.

## 3. Используемые сервисы и методы API

| Сервис | Метод | Для чего |
|---|---|---|
| Campaigns | get | Список кампаний, их состояние и статус |
| Reports | (отчёт `CAMPAIGN_PERFORMANCE_REPORT`, TSV) | Вся статистика: показы, клики, расход по дням и кампаниям |
| Ads | add | Создание текстовых объявлений в выбранной группе, только по явному подтверждению сотрудника |

Статистика запрашивается только через сервис Reports. Методы `AgencyClients`, `KeywordBids` и автоматическое управление ставками приложение **не использует** (в шаблоне они приведены как пример для агентств и биддеров).

Запрашиваемые права в Яндекс ID: доступ к API Директа **[заполнить: в форме приложения выбрать ровно «Использование API Директа»; других прав не запрашивать]**.

## 4. Нагрузка и экономия баллов

- Отчёты запрашиваются в режиме `processingMode: auto`; при ответах 201/202 приложение ждёт интервал `retryIn` и повторяет запрос (не более 8 попыток), а не опрашивает API в цикле.
- Отчёты запрашиваются по действию пользователя (выбор периода), фоновых опросов нет. Ожидаемая нагрузка — единицы отчётов в день.
- Параметры `skipReportHeader` и `skipReportSummary` отключают служебные строки в ответе; деньги запрашиваются в микро-единицах (`returnMoneyInMicros`) для точности.
- Список кампаний запрашивается один раз при открытии страницы «Кампании».
- Объявления отправляются вручную, по одному объявлению на запрос; массовая отправка и автоматические циклы не предусмотрены.
- Ожидаемый объём: 2 кампании, около 10–50 объявлений **[заполнить, если планы шире]**.

## 5. Текущее состояние приложения (честно)

- Реализован рабочий прототип (Python, стандартная библиотека): авторизация OAuth, страницы «Кампании», «Объявления», «Отчёты», клиент API.
- Скриншоты в `API/screenshots/` сняты с реально запущенного прототипа в **демо-режиме**: данные тестовые, запросы в API Директа не отправлялись (в интерфейсе об этом написано в жёлтой плашке).
- Клиент к реальному API и песочнице написан, но **ещё не проверен** на живом токене. Перед подачей заявки рекомендуется один раз пройти сценарий в песочнице `api-sandbox.direct.yandex.com` и заменить скриншоты на снятые в этом режиме.
